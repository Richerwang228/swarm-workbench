# Swarm 100 Observatory Design

> Superseded in part by the user's live-agent requirement. The deterministic
> benchmark remains as CI and scheduler evidence, while the product runtime now
> supports up to 100 provider-backed worker Agents. See
> [Live 100](../LIVE_100.md).

## Goal

Add a portfolio-grade scale demonstration that is visually memorable and
technically honest: 100 logical simulated agents, process-wide bounded
concurrency, deterministic recovery injection, complete event traces, and a
machine-readable benchmark report.

## Product claim

The release may claim:

> Supports reproducible runs of 100 logical simulated agents with
> process-wide bounded concurrency and full event traces.

This benchmark itself must never be presented as live-model evidence.

## Runtime model

`agent_count` is the amount of logical work. `max_concurrency` is the
per-run in-flight limit. A process-wide capacity manager provides the final
upper bound across all runs.

Each benchmark agent has a stable ID, deterministic role, deterministic
work duration, and deterministic fail-once decision derived from the run seed.
Queued agents are visible before they acquire a worker slot.

The benchmark emits the same task, todo, agent, tool, and content events as
other modes, plus benchmark progress and report events.

## Report

The report includes:

- requested, completed, failed, and recovered agents;
- process and run peak concurrency;
- elapsed time and throughput;
- p50/p95 queue wait and execution duration;
- seed, workload configuration, and a semantic SHA-256;
- an explicit `simulated: true` marker.

The semantic hash excludes event IDs, timestamps, and scheduling order.

## Interface

The console adds a `SWARM 100` mode. At scale it switches from full cards to
a dense 10x10 status matrix, aggregate metrics, and a bounded task/activity
view. The interface always displays `SIMULATED BENCHMARK`.

## Verification gate

- Exactly 100 unique agents reach a terminal state.
- Peak run concurrency never exceeds the request limit.
- Peak process concurrency never exceeds the global limit across concurrent
  runs.
- Identical seeds produce identical semantic hashes.
- Injected fail-once agents recover without slot leakage.
- A late SSE subscriber receives the complete scale trace.
- Python tests, frontend checks, production build, dependency audits, CodeQL,
  and secret scanning remain green.
